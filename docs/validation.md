## 第二次迭代

加入绑定原行 ID 与文件 SHA-256 的人工修正，原值、理由、修改内容、重跑结果都保留。增加原币种金额分类对账、Excel、离线 HTML、命令行入口和双语说明。

修正相关测试先跑出 12 项失败，核心实现后 42 项通过。集成阶段继续用真实工作簿发现并修正以下问题：

| 发现 | 处理与验证 |
| --- | --- |
| `￥-30.50` 退款金额被误判，接纳只有 111 行 | 支持负号在人民币符号前后，仍拒绝双负号。实际文件恢复为 112 行 |
| 制表工具输出的命名空间前缀、绝对表格关系路径无法被 ExcelJS 直接读取 | 在内存副本中用 XML 解析器按命名空间处理标签和表格路径，原文件与哈希保持不变。十个实物文件均读取通过 |
| 跨币种原金额相加会产生错误口径 | 原币种分别对账。金额无法解析或币种改变时，不计算不成立的修正差额 |
| 客户名 `*` 会被条件公式解释为通配符，大小写不同的客户也会混在一起 | 明细保留数字客户分组。八种特殊名称与大小写差异经过实际重算，均只计入自己的金额和行数 |
| 空工作表没有行，导致文件数遗漏 | 独立保留工作表清单，空表仍有文件名、哈希和结构问题 |
| 状态 `constructor` 或 `__proto__` 命中对象继承属性 | 使用显式自有属性白名单，异常状态进入复核 |
| 中途重复表头换列后仍用旧映射 | 每个数据块更新映射；歧义块隔离，遇到下一个明确表头后恢复 |

独立规格审查和独立代码质量审查均完成。上述问题修复后复审通过。
