# 十份销售订单表合并演示

目标：展示一项可向小团队交付的服务。输入十份格式不一致的模拟 `.xlsx`，输出一份可核对的汇总工作簿，以及机器可读审计记录。只验证数据处理与交付可行性，不把模拟演示当成已验证的付费需求。

## 取舍

选择本地命令行（CLI / Command-Line Interface）工具，文件不上传服务。不做登录、数据库或在线模型。相比直接拼表，多保留异常与来源；相比完整网页应用，先验证汇总准确性。生成一个可直接打开的 HTML 报告供非技术客户查看。

场景：同币种人民币销售订单明细。业务唯一键为 `order_id + line_id`，不是只用订单号；允许一单多行及负数量退货。必要字段：订单号、行号、日期、客户、商品编码、数量、单价、金额、币种、状态。

## 数据与规则

- 十个输入文件使用不同列别名、顺序、标题行、日期格式和数字表示，包含说明页、空行、重复表头、合计行。
- 原始单元格值、文件 SHA-256、工作表和 Excel 行号全部保留。金额用整数分，不用浮点直接累计。
- 日期仅接受明确格式及工作簿实际日期。含歧义的斜线日期、未知币种、缺失标识、非法数值、金额不符等转入异常；不得猜测或置零。
- 公式单元格保守转人工复核，不执行外部链接，不把其缓存结果当可信原始值。
- 同唯一键且全部规范字段相同的行标记重复，保留来源和引用；任何同键不同内容的组整组待复核，不按文件顺序自动选赢家。
- 行数恒等式：数据行 = 接纳行 + 重复行 + 待复核行。说明/表头/合计/空行有独立跳过日志；未知格式工作表明确报告。
- 金额核对覆盖所有可解析原始金额：原始金额 = 接纳 + 重复 + 待复核中可解析金额。无效金额独立计数，不能声称其数值已对账。

## 两次迭代

0. 初版：基础标准化、无声丢行检查、十文件样例与独立预期控制值。
1. 第一次迭代：针对重复冲突、重复表头、非法日期和金额、公式、多工作表/未知字段的边界测试，整组隔离冲突，输出逐文件对账。
2. 第二次迭代：增加绑定原始文件哈希与单元格内容的人工修正 JSON；改前改后与理由可追溯，源文件不变。重跑不得把旧输出当输入；加上可读 Excel、离线 HTML 报告和双语文档。

## 输出

`summary.xlsx`：汇总（主要指标与按客户金额）、明细（可筛选）、待复核（原因与原值）、来源（逐行审计与跳过原因）。摘要只读取明细业务结果，审计不反向成为业务数据。另有 `audit.json`、`report.html`。

默认 demo 包含已知异常。生成器独立计算基础控制值并保存 `expected.json`，合并器绝不读取此文件。验证比较实际唯一键、金额分、分类数量和每条输入的去向，不只看文件能否打开。

运行时采用可公开安装的 ExcelJS 读写适配器。当前制作样例与最终交付表时优先使用工作环境提供的 Artifact Tool；该工具非公开 npm 依赖，不把其私有路径写入运行入口或提交依赖。
